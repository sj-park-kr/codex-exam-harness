# to-e2e

브라우저로 실행할 E2E 시나리오 문서를 만든다. 인터뷰하지 않는다. 이 스킬은 실행하지 않는다(실행은 `$run-e2e`).

## 1. 근거 읽기
완성된 구현을 대상으로 한다. 무엇을 확인할지는 문서에서, 어떻게 조작할지는 구현에서 가져온다.
- 기대 동작: `docs/PRD.md`(규칙·예외·AC), `docs/ARCHITECTURE.md`(계산 해석), `README.md`(실행 명령·출력 계약)의 필요한 부분. 과제가 지정한 문서가 있으면 그걸 쓴다. PRD의 규칙·예외마다 시나리오를 하나 이상 만든다.
- 조작 방법: 구현된 화면 코드에서 경로·화면 라벨(버튼·입력·탭 이름)·업로드 형식을 그대로 가져온다. Playwright가 `getByRole`·`getByLabel`·`getByText`로 찾을 이름이다.
- 구현의 출력 숫자는 기대값으로 복사하지 않는다. 구현과 PRD가 다르면 PRD 기준으로 기대값을 쓰고 차이를 답변에 올린다.
- 제공 데이터의 기대값은 `tests/e2e/expected/`에 둔 독립 스크립트로 원본에서 산출한다. PRD·ARCHITECTURE의 규칙·공식만 쓰고 앱 코드를 import하지 않는다. 문서에는 산출 방법(공식·적용 순서)과 결과 표를 같이 적는다.

## 2. 문서 구조 (`docs/E2E_SCENARIOS.md`)
머리에 `작성일: YYYY-MM-DD. 상태: **시나리오 작성 완료, 실제 E2E 미실행**.`

1. **판정 원칙**: 기대값의 근거 문서. 정확 비교(건수·금액·날짜·분류, 허용 오차 0) / 조건 비교(여러 정답이 가능한 ID·경로는 규칙으로 판정, 생성 ID·시각은 실제값 기록) / 미실행·차단(실행 안 한 항목은 합격 아님, 선행 실패면 원인과 차단 시나리오를 남김).
2. **실행 준비와 기록**: 테스트용 DB·작업 복사본(기존 DB 삭제·교체 금지), 계정 준비(역할별 2개 이상, 비밀번호는 문서에 적지 않음), README의 실행 명령과 `0.0.0.0:<포트>`, 역할별 별도 브라우저 프로필. 상태는 `미실행 / 합격 / 실패 / 선행 실패로 차단`. 시나리오마다 쓸 기록 양식 표:

   | 기록 항목 | 입력 |
   |---|---|
   | 실행 ID / 시나리오 ID / 실행 일시 / 앱 커밋 | 미기록 |
   | 브라우저 / 자료 세트 / 관련 ID | 미기록 |
   | 비교 항목 | 기대값과 대응하는 화면·필드 |
   | 기대값 | 실행 전 기입 |
   | 시스템 실제값 | 미실행 |
   | 차이 / 판정 | 미실행 |
   | 증거 위치 / 실패 원인 / 재시험 결과 | 미기록 |

3. **독립 기대값 자료 세트**: 손으로 계산할 수 있는 작은 합성 자료를 경계값마다 만든다(정원 경계 N, N+1 등). 파일은 `tests/fixtures/e2e/<세트>/`에 제공 파일과 같은 헤더·인코딩·줄바꿈으로 저장하고 그 폴더 `AGENTS.md`에 세트별 용도를 적는다. 세트마다 왜 그 값이 나오는지 계산 근거와 기대값 표를 적는다. 실제 개인정보를 복사하지 않는다. 제공 자료는 1절의 독립 스크립트로 산출한 값만 기대값으로 쓰고, 산출 안 한 총계는 숫자를 지어내지 않는다.
4. **웹 시나리오**: `### Exx 제목 — ACxx` 형식. 각각
   - 전제: 자료 세트, 선행 시나리오, 계정.
   - 조작: 화면 라벨 그대로, 화살표로 순서.
   - 기대: 화면에서 확인할 값과 판정 기준. 숫자는 3절 표를 참조.
   순서는 로그인·권한 → 핵심 흐름(입력→처리→결과) → 확정·조회 → 내보내기 → 오류·롤백·기존 결과 보존 → 재시작 보존 → 경계 규칙 → 제공 자료.
5. **화면 조작으로 만들기 어려운 경계와 장애**: 재시작·장애 주입·외부 연결 차단처럼 자동화가 어려운 것과 대체 검증 방법.
6. **완료 판정과 남는 한계**: 우선 실행 순서, 완료 조건(모든 필수 시나리오에 실제값·증거·판정), 테스트가 증명하지 못하는 것.

## 3. 점검
- PRD의 모든 AC가 최소 한 시나리오 제목에 있다. 빠진 AC는 이유를 6절에 적는다.
- README가 요구한 저장·재시작 보존·실패 시 기존 결과 보존 시나리오가 있다.
- 비밀번호·세션값·실제 개인정보가 문서와 fixture에 없다.
- 문서를 만들었으면 `docs/AGENTS.md`(없으면 루트 `AGENTS.md`)에 링크와 읽을 시점("E2E 실행·기록 전")을 추가한다.

## 4. 답변
만든 시나리오 수, AC 매핑 누락, 기대값을 못 정한 항목만 짧게. 다음 단계는 `$run-e2e`.
