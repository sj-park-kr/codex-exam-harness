# to-questionnaire

실무자 에이전트에게 한 번에 보낼 질문지를 만든다. 결과물을 바꾸는 빈칸만 묻고, 이미 답이 있거나 "모름"으로 끝난 것은 다시 묻지 않는다.

## 1. 빈칸 찾기
- README·제공 문서는 필요한 부분만 읽는다. 파일 전체 출력 금지.
- 제공 데이터는 앞 몇 줄로 헤더·형식만 보고, 전체 내용은 집계 스크립트로 본다. 스크립트는 작업공간 밖 임시 폴더에 두고 집계 결과만 출력한다(행·개인정보 출력 금지).
  - 파일별 행 수, 컬럼별 빈칸 수, 키 중복
  - 상태·구분 컬럼의 값 분포(폐지·퇴사·휴무처럼 처리 방식이 갈리는 값)
  - 파일 간 참조 누락(다른 파일에 없는 ID를 가리키는 행)
  - 날짜 범위, 요일·기간별 건수, 범위 밖·형식 오류 값
  - 0·음수·극단값
- 결과는 `docs/QUESTIONS.md`의 "데이터 관찰" 절에 한 줄씩 적는다(`파일: 현상 — 건수`). 문서에 처리 규칙이 없는 예외만 질문으로 올리고, 질문의 "왜 필요한가"에 건수를 적는다.
- 아래 항목마다 문서에 답이 있는지 본다. 있으면 묻지 않고 상태를 "문서 확정"으로 적는다.
  - 사용자·역할
  - 입력 데이터의 의미·단위·기준일
  - 출력·화면에서 꼭 봐야 하는 것
  - 업무 규칙의 기준값과 예외
  - 목표 지표: 무엇이 "좋은 결과"인가, 기존 방식과 어떻게 비교하나
  - 실행 빈도와 데이터 규모: 얼마나 자주 실행되나, 한 번에 다루는 데이터는 어느 정도인가. 답이 없을 때 추천안은 "드물게 실행, 제공 데이터 규모"
  - 범위 밖
  - 완료 기준
- 기술 선택(언어, 저장 방식, 인증 방식, 알고리즘)은 실무자 질문지에 넣지 않는다. 필요하면 추천안과 함께 사용자에게 묻는다.
- `docs/QUESTIONS.md`가 이미 있으면 거기 있는 질문은 다시 넣지 않는다.

## 2. 질문지 쓰기
`docs/QUESTIONS.md`에 아래 형식으로 쓴다. 최대 10문항, 중요한 순서, 한 문항에 한 가지만.

<questions-template>
# 실무자 질문

| # | 질문 | 왜 필요한가 | 답이 없을 때 추천안 | 답 | 상태 |
|---|---|---|---|---|---|
| Q1 | ... | 이 답에 따라 무엇이 달라지나 한 줄 | ... | | 미답변 |

상태: 미답변 / 확정 / 모름 / 문서 확정 / 사용자 결정

## 데이터 관찰
- 파일: 현상 — 건수
</questions-template>

답변에는 실무자에게 그대로 붙여 넣을 메시지만 준다: 맥락 1~2문장 + 번호 붙은 질문. 파일 설명은 생략한다.

## 3. 답 반영
- 사용자가 실무자 답을 붙여 넣으면 "답"과 "상태"를 채운다.
- "모름"은 실무자에게 다시 묻지 않는다.
- 실무자는 일부 질문에만 답할 수 있다. 답이 안 온 질문은 결과를 크게 바꾸는 것만 골라 후속 질문으로 다시 묻는다. 답 때문에 새로 생긴 빈칸과 합쳐 최대 3개, 후속 질문은 한 번만 보낸다.
- 모름과, 후속 질문에 넣지 않은(또는 후속 질문에도 답이 없는) 미답변은 직접 정하지 않는다. "답이 없을 때 추천안"을 붙여 사용자에게 한 번에 묻는다("Q3) 추천: …. 다르면 번호만"). 사용자가 고른 것을 상태 "사용자 결정"으로 적고 DECISIONS.md에 한 줄 남긴다(결정 / 이유 / 버린 대안 / 검증).
